# OT Clinical Reasoning Assistant — Agent Operating Instructions

---

# Purpose

This document defines the operational rules, product constraints, architectural philosophy, and workflow expectations for any AI agent contributing to this project.

Agents should optimize for:
- operational clarity
- workflow usefulness
- cognitive compression
- clinical realism
- implementation practicality

Agents should avoid:
- unnecessary expansion
- excessive abstraction
- speculative architecture
- workflow complexity
- narrative bloat

---

# Product Summary

The platform is a structured clinical reasoning assistant for adult home health Occupational Therapy.

Primary goals:
- reduce clinician cognitive overload
- improve prioritization clarity
- accelerate treatment planning
- improve environmental realism
- support operational decision-making

The system is not intended to:
- replace therapist judgment
- function as autonomous AI
- generate unrestricted treatment plans
- maximize narrative output

The deterministic reasoning engine is authoritative.

AI serves as a constrained synthesis and workflow interpretation layer.

# Critical Operational Rules

## 1. Reduce Cognitive Load
Outputs should simplify clinician thinking, not expand it.

Avoid:
- excessive text
- repeated concepts
- redundant explanations
- unnecessary frameworks

---

## 2. Prioritize Workflow Clarity
Recommendations should improve:
- rapid orientation
- treatment prioritization
- actionable execution
- visit readiness

---

## 3. Maintain Environmental Realism
Recommendations must reflect:
- real residential environments
- practical transfer limitations
- caregiver limitations
- safety constraints
- realistic implementation feasibility

---

## 4. Deterministic Logic Is Authoritative
Do not override deterministic reasoning with generative assumptions.

AI should:
- organize
- synthesize
- compress
- clarify

AI should not:
- invent unsupported clinical reasoning
- contradict deterministic outputs
- speculate beyond provided inputs

---

## 5. Avoid Generic AI Language
Avoid:
- vague motivational phrasing
- inflated clinical language
- generic treatment advice
- repetitive AI-style narrative

Outputs should feel:
- operational
- concise
- clinically grounded
- workflow-oriented

# Coding Guidance

When providing implementation guidance:
- provide exact file paths
- provide exact code to find
- provide exact replacement blocks
- avoid assumptions
- avoid rewriting large unrelated sections
- proceed step-by-step unless otherwise requested

Preferred workflow:
- one scoped change at a time
- clear implementation boundaries
- maintain architectural consistency
