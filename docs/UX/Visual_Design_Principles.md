# OT Clinical Assistant — Visual Design Principles v1

## Purpose

The OT Clinical Assistant is not a dashboard.

It is not a reporting tool.

It is not an analytics platform.

It is a clinical operations command center.

The interface exists to reduce cognitive effort by presenting the current clinical reality, meaningful change, required attention, and next action with maximum clarity and minimum visual noise.

Success is not measured by how modern, beautiful, or visually impressive the interface appears.

Success is measured by how quickly a clinician understands the patient situation and confidently proceeds with treatment.

The product should feel:

* Calm
* Clear
* Professional
* Trustworthy
* Focused
* Decisive

The product should never feel:

* Flashy
* Futuristic
* Experimental
* AI-centric
* Dashboard-heavy
* Over-designed

---

# Principle 1 — Current Reality Owns the Page

The most important information on the screen is the current clinical reality.

Everything else exists to support understanding of that reality.

The clinician should immediately understand:

* What is happening now
* Why it matters
* What requires attention

without searching.

Current Focus should always remain the highest-authority element in the Command Center.

No secondary content should visually compete with it.

---

# Principle 2 — Workflow Over Cards

The Command Center is a workflow.

It is not a collection of independent widgets.

The clinician experience should feel like:

Current Reality
↓
Status
↓
Change
↓
Attention
↓
Action

and not:

Card
Card
Card
Card
Card

Visual design should reinforce the clinical thought process rather than emphasize component boundaries.

---

# Principle 3 — Typography Creates Hierarchy

Hierarchy should be communicated primarily through:

1. Position
2. Size
3. Typography
4. Spacing
5. Contrast
6. Color

Typography is the primary organizational tool.

Borders, backgrounds, and containers are supporting tools.

When possible:

* stronger typography
* clearer structure
* better spacing

should be preferred over:

* more color
* more borders
* more decoration

---

# Principle 4 — Color Must Have Meaning

Color is a clinical signal.

Color is not decoration.

Every color used in the interface should communicate meaning.

Preferred meanings:

| Meaning  | Purpose                      |
| -------- | ---------------------------- |
| Neutral  | Normal information           |
| Positive | Improvement                  |
| Warning  | Attention required           |
| Negative | Decline or elevated concern  |
| Action   | Next step or required action |

Avoid:

* module colors
* section colors
* category colors
* decorative accents

Clinicians should not need to learn a color legend.

Meaning should be obvious.

---

# Principle 5 — Attention Is Earned

Visual emphasis carries cognitive cost.

Every element competing for attention makes the interface harder to scan.

If everything is emphasized, nothing is emphasized.

Visual emphasis should be reserved for:

* current clinical reality
* significant change
* required attention
* immediate action

Reference information should remain available without demanding attention.

---

# Principle 6 — Whitespace Is Functional

Whitespace is not decoration.

Whitespace creates:

* separation
* hierarchy
* pacing
* comprehension

The purpose of whitespace is to reduce interpretation effort.

Layouts should feel deliberate rather than dense.

Whitespace should guide the eye through the clinical workflow.

---

# Principle 7 — Reduce Visual Noise

Every visual element should justify its existence.

Question every:

* border
* background
* pill
* divider
* icon
* accent
* label

If an element does not improve understanding, it should be removed or reduced.

The cleanest interface is not the one with the fewest elements.

It is the one with the fewest unnecessary elements.

---

# Principle 8 — Progressive Disclosure Over Clutter

Primary workflow information should always be visible.

Secondary information should be available when needed.

Supporting details should not compete with primary clinical answers.

The interface should reward deeper exploration without requiring it.

---

# Principle 9 — Calm Confidence

The product should feel trustworthy before it feels impressive.

The interface should communicate:

"I understand the situation."

not:

"Look how much information I contain."

Confidence comes from:

* clarity
* consistency
* restraint
* predictability

not from visual complexity.

---

# Principle 10 — Clinical Utility Is The Ultimate Measure

Every design decision should be evaluated through one question:

Does this help a clinician understand the patient situation faster and act with greater confidence?

If the answer is no, the design should be reconsidered.

Clinical utility takes precedence over aesthetics.

The highest compliment a clinician can give this product is not:

"Beautiful."

It is:

"Easy."

---

# Design Direction Statement

The OT Clinical Assistant should feel like:

**The calm confidence of an Apple product, the operational clarity of Linear, and the seriousness of a clinical workstation.**

The interface should communicate current reality, meaningful change, required attention, and next action with maximum clarity and minimum visual noise.

Simplicity is achieved through hierarchy, restraint, typography, and whitespace—not through removing clinically relevant information.
