# Case Workspace Layout Map v1

---

# Purpose

This document defines the practical screen orchestration and layout structure for the Case Workspace experience.

This document translates:
- workflow philosophy
- workspace architecture
- operational hierarchy
- continuity philosophy

into:
```txt
practical clinician-facing workspace structure
```

This document governs:
- section ordering
- visual pacing
- above-the-fold structure
- sticky orientation behavior
- collapse defaults
- operational hierarchy rendering
- continuity surfacing
- progression visibility
- density management
- mobile orchestration

This is the final UX orchestration layer before frontend implementation.

---

# Core Workspace Design Goal

The workspace should feel:

```txt
operationally intelligent
```

NOT:

```txt
AI-generated
```

The clinician should feel:
- oriented quickly
- operationally grounded
- cognitively supported
- progressively informed
- never overwhelmed

The workspace should progressively reveal:
- instability
- continuity meaning
- operational pressure
- execution support
- refinement detail

in a controlled sequence.

---

# Workspace Structural Philosophy

The workspace should behave like:

```txt
a progressively intelligent operational workspace
```

NOT:
- a report
- a dashboard
- stacked generated cards
- equally weighted sections
- an AI narrative dump

The page must establish:
- orientation first
- instability second
- execution third
- refinement fourth
- history fifth

That sequencing is critical.

---

# Desktop Layout Structure

## Overall Layout

Recommended structure:

| Region | Purpose |
|---|---|
| Sticky Top Orientation Bar | Persistent continuity awareness |
| Main Workspace Column | Primary operational interpretation |
| Right-Side Support Rail | Operational preview + continuity compression |
| Lower Workspace Expansion | Refinement + longitudinal history |

The page should visually prioritize:

```txt
vertical operational flow
```

NOT:

```txt
horizontal dashboard density
```

---

# Above-the-Fold Structure

The first screen visible without scrolling is the most important part of the product.

The clinician should understand within:

```txt
15 seconds
```

- what is unstable
- what matters most
- what pressures dominate
- how fragile the condition is
- whether reassessment pressure exists

WITHOUT:
- opening panels
- reading paragraphs
- navigating tabs

---

# Above-the-Fold Layout Order

## 1. Sticky Operational Header

Persistent top strip.

Always visible.

Height should remain compact.

Contains:
- patient identity
- diagnosis
- target activity
- progression phase
- continuity condition
- reassessment pressure
- operational state label

This is:

```txt
persistent clinical orientation
```

---

## 2. Current Operational State Panel

Highest visual dominance.

Immediately below header.

This becomes:

```txt
the operational anchor of the workspace
```

Should visually communicate:
- dominant instability
- operational fragility
- environmental pressure
- caregiver feasibility
- immediate operational concern

This should NOT resemble:
- a generated summary
- AI prose
- recommendation paragraphs

---

## 3. Progression + Continuity Row

High-level operational evolution visibility.

Compact but visually elevated.

Should contain:
- progression state
- continuity condition
- reassessment pressure
- operational drift indicators
- continuity alerts

This row becomes:

```txt
longitudinal orientation
```

NOT:

```txt
hidden metadata
```

---

## 4. Immediate Operational Guidance

Immediately actionable.

Includes:
- session priorities
- caregiver support expectations
- environmental risk focus
- transfer cautions
- execution concerns

This should feel:

```txt
clinically actionable
```

NOT:

```txt
recommendation-heavy
```

---

# Right-Side Support Rail (Desktop)

## Purpose

Provide compressed operational reinforcement without disrupting the primary workspace flow.

This rail should remain:
- compact
- visually quiet
- always useful
- cognitively lightweight

---

## Recommended Contents

### Operational Snapshot

Compressed summary:
- primary instability
- target activity
- caregiver dependence
- environmental complexity
- reassessment pressure

---

### Continuity Indicators

Compact continuity visibility:
- operational drift
- continuity condition
- instability persistence
- reassessment triggers

---

### Quick Actions

Minimal operational controls:
- regenerate
- reassessment update
- continuity checkpoint review
- edit operational details

Avoid:
- dense button clusters
- workflow explosion
- excessive controls

---

# Mid-Workspace Structure

After above-the-fold orientation, the workspace deepens progressively.

The clinician should feel:

```txt
I understand the case enough to go deeper if needed.
```

NOT:

```txt
I still don't know what matters.
```

---

# Mid-Workspace Layout Order

## 1. Environmental Interpretation

Focused environmental pressure interpretation.

NOT:
- raw environment dump
- exhaustive field rendering

Should prioritize:
- operational consequences
- unsafe transitions
- participation barriers
- setup bottlenecks

---

## 2. Caregiver + Feasibility Interpretation

Focused caregiver realism.

Should prioritize:
- realistic support capacity
- caregiver strain
- supervision limitations
- feasibility mismatch
- caregiver dependence

Should feel:

```txt
operationally grounded
```

NOT:

```txt
idealized support planning
```

---

## 3. Transfer + Mobility Interpretation

Focused transfer fragility interpretation.

Should prioritize:
- unsafe transitions
- fatigue patterns
- transfer instability
- movement bottlenecks
- environmental interaction

This should become:

```txt
functional operational movement understanding
```

NOT:

```txt
raw mobility data rendering
```

---

# Refinement Layer

## Philosophy

This layer should feel:

```txt
optional but valuable
```

NOT:

```txt
required to understand the case
```

All refinement content should default:
- collapsed
- compressed
- low dominance

---

# Refinement Components

Includes:
- caregiver scripts
- ADL privacy modules
- equipment feasibility
- advanced environmental detail
- advanced continuity interpretation
- reasoning transparency
- operational nuance

---

# Collapse Rules

## Default State

Collapsed.

Always.

Unless:
- severe instability
- high reassessment pressure
- severe caregiver mismatch
- major safety escalation
- severe environmental fragility

---

## Auto-Expansion Rules

Only auto-expand:
- highest operationally relevant refinement
- one section maximum initially

Avoid:

```txt
accordion explosion
```

---

# Continuity History Placement

## Location

Bottom workspace region.

Should feel:

```txt
longitudinal reference
```

NOT:

```txt
primary workspace content
```

---

# Continuity History Layout

Each continuity checkpoint should surface:
- timestamp
- operational state
- reassessment trigger
- progression phase
- continuity condition
- major operational change

This should visually resemble:

```txt
clinical operational evolution
```

NOT:

```txt
software versions
```

---

# Narrative Density Rules

The workspace should aggressively suppress:
- repeated recommendations
- duplicated interpretation
- AI verbosity
- large prose blocks
- unnecessary narrative explanation

Prefer:
- compressed operational statements
- high-signal summaries
- layered interpretation
- expandable detail

The clinician should rarely encounter:

```txt
large uninterrupted text walls
```

---

# Section Interaction Rules

## Allowed

- progressive expansion
- contextual detail reveal
- lightweight collapse
- continuity exploration
- operational drill-down

---

## Avoid

- tab labyrinths
- multi-panel competition
- dashboard overload
- modal dependence
- excessive clicks
- hidden critical information

---

# Scroll Philosophy

The workspace should scroll like:

```txt
deepening operational understanding
```

NOT:

```txt
stacked report sections
```

The further the clinician scrolls:
- the more optional
- the more detailed
- the more refinement-oriented
the information becomes.

---

# Mobile Layout Strategy

## Mobile Philosophy

Mobile should preserve:
- operational orientation
- continuity visibility
- instability visibility
- reassessment pressure
- progression state

while aggressively compressing:
- refinement detail
- transparency systems
- advanced operational nuance

---

## Mobile Layout Order

1. Sticky orientation strip
2. Operational state
3. Progression + continuity
4. Immediate operational guidance
5. Optional expansion
6. Continuity history

---

# Information Competition Rules

The following should NEVER visually compete equally:
- operational instability
- refinement modules
- reasoning transparency
- continuity history
- AI narrative sections

Operational instability must ALWAYS dominate.

---

# Workspace Emotional Tone

The workspace should feel:
- calm
- trustworthy
- clinically intelligent
- operationally grounded
- continuity-aware
- low-friction

NOT:
- experimental
- AI-chaotic
- visually noisy
- narratively overwhelming
- technically exposed

---

# Success Criteria

A clinician should be able to:
- orient within 15 seconds
- understand instability within 30 seconds
- identify dominant pressures quickly
- recognize reassessment urgency quickly
- understand operational fragility quickly
- access deeper refinement only if needed

without:
- excessive reading
- multiple clicks
- dashboard interpretation burden
- backend ontology exposure

The workspace should feel like:

```txt
a continuity-aware operational command center
```

NOT:

```txt
an AI-generated report viewer
```
