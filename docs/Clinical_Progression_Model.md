# Clinical Progression Model

---

# Purpose

This document defines the clinical progression model that governs longitudinal reasoning within the OT Clinical Assistant.

The purpose is to define:

- what progression actually represents
- what longitudinal change means
- what should be captured over time
- how treatment priorities evolve
- how reassessment changes operational focus

This model serves as the clinical foundation beneath:

- continuity architecture
- progression architecture
- reassessment architecture
- longitudinal data capture
- operational prioritization

---

# Core Clinical Principle

Occupational Therapy progression is not primarily the story of:

- visits completed
- treatment minutes delivered
- interventions performed
- documentation produced

Occupational Therapy progression is primarily the story of:

- occupational performance evolution
- assistance level reduction
- barrier resolution
- milestone attainment
- operational priority evolution

---

# Core Clinical Loop

Evaluation
↓
Identify Dominant Barrier
↓
Establish Operational Priority
↓
Provide Intervention
↓
Reassess Change
↓
Evaluate Milestone Achievement
↓
Identify New Dominant Barrier
↓
Update Operational Priority
↓
Repeat

---

# Longitudinal Unit Of Progress

The system should primarily track:

- occupational performance
- assistance levels
- dominant barriers
- milestone attainment
- operational priority transitions

The system should not primarily track:

- visit counts
- treatment counts
- narrative visit history
- documentation volume

# Progression Check Hierarchy

Longitudinal progression should be interpreted using the following hierarchy:

## 1. Barrier Evolution

Primary organizing principle.

The most important question in longitudinal reasoning is:

> What is limiting occupational performance now?

Progression should be understood primarily through the resolution, reduction, emergence, or replacement of dominant barriers.

Barrier evolution determines:

- operational priority
- treatment focus
- reassessment significance
- progression direction

---

## 2. Functional Change

Evidence layer.

Functional change demonstrates whether progression occurred.

Examples:

- improved bathing performance
- improved transfer performance
- reduced assistance requirements
- increased occupational participation

Functional change provides observable evidence of barrier evolution.

---

## 3. Milestone Achievement

Interpretation layer.

Milestones convert functional change into clinically meaningful progression events.

Examples:

- safe shower transfer achieved
- standing tolerance goal achieved
- supervision level achieved
- independent task completion achieved

Milestones help explain the clinical significance of progression.

---

# Clinical Progression Flow

Longitudinal reasoning should generally follow this sequence:

Functional Change
↓
Barrier Re-Evaluation
↓
Milestone Determination
↓
Operational Priority Adjustment

The purpose of longitudinal tracking is not merely to record change.

The purpose is to determine:

> What should treatment focus on next?

---

# Functional Baseline Model

The baseline represents the earliest authoritative functional state available.

It establishes:
- occupational performance baseline
- assistance level baseline
- caregiver baseline
- environmental baseline
- safety baseline

All future comparison should reference this baseline.

---

# Functional Milestone Model

A milestone represents a meaningful improvement in occupational performance.

Examples:

- Max Assist → Mod Assist
- Mod Assist → Min Assist
- Min Assist → Supervision
- Supervision → Independent
- Safe shower transfer achieved
- Reduced caregiver dependence
- Improved standing tolerance
- Reduced cueing requirement

Milestones represent evidence that progression has occurred.

---

# Barrier Evolution Model

Progression occurs through barrier evolution.

## Active Barrier
The primary factor currently limiting participation.

## Emerging Barrier
A barrier becoming increasingly relevant but not yet dominant.

## Resolved Barrier
A barrier that no longer significantly limits performance.

Examples:
- balance
- endurance
- pain
- cognition
- safety awareness
- caregiver dependence
- environmental constraints

---

# Operational Priority Evolution

Operational priorities should evolve as barriers evolve.

| Dominant Barrier | Operational Priority |
|------------------|---------------------|
| Unsafe Transfer | Safety Stabilization |
| Transfer Mechanics | Transfer Training |
| Standing Tolerance | Functional Participation |
| Endurance | Occupational Endurance |
| Safety Awareness | Independence Development |
| No Significant Barrier | Sustainability |

Operational priority changes should always be explainable through barrier evolution.

---

# Clinical Significance Model

Longitudinal change is only meaningful when clinical significance exists.

Examples:

- reduced caregiver burden
- increased independence
- improved safety
- improved participation
- improved task completion
- reduced fall risk

---

# Progression Evidence Model

Meaningful progression requires evidence from:

- occupational performance
- assistance levels
- caregiver state
- environmental state
- safety status
- milestone attainment

The system should avoid inferring progression from visit count alone.

---

# Baseline vs Follow-Up Rules

## Evaluation

Establish:
- current function
- dominant barriers
- operational priority
- caregiver state
- environmental state
- milestone target

## Follow-Up

Capture:
- what changed
- what stayed the same
- milestone achieved
- dominant barrier shift
- operational priority shift
- next milestone target
- reassessment triggers

---

# Governance Rule

Before introducing any longitudinal feature, ask:

Does this improve understanding of:

- occupational performance evolution
- milestone attainment
- barrier evolution
- operational priority evolution

without increasing cognitive burden?

If not:

- simplify it
- defer it
- reject it
